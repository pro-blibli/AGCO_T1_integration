Integration Architecture

AGCO's B2B Dealer E-Commerce portal (Hybris) integrates with Talon.One's Integration API to validate promotional eligibility, apply tiered discounts, and transfer verified orders to local ERP systems. Below is the end-to-end data flow.

01
Dealer logs in
Hybris authenticates dealer, resolves account code
→
02
Profile sync
Dealer profile & vendor attributes pushed to Talon.One
→
03
Promo selected
Campaign name entered; parts list loaded from Hybris
→
04
Session update
Cart items + promo code sent to Talon.One session endpoint
→
05
Effects returned
Discounts, free freight, MOQ blocks applied to cart
→
06
Order to ERP
Validated order transferred to S4/local ERP system
Integration API
Hybris ↔ Talon.One
All promotional logic lives in Talon.One's Rule Engine. Hybris sends context; Talon.One returns effects.
Campaign Manager
Back-office setup
Commercial team configures promo rules, tiers, collections and dealer eligibility via Campaign Manager.
ERP Bridge
Talon.One response → S4
Talon.One's effects response is forwarded via AGCO's middleware layer to S4 for order creation and fulfilment.
Step 1 — Profile Endpoint

Dealer & Vendor Profile Ingestion

Before any promotional validation can occur, AGCO's Hybris system must sync dealer account data and vendor-specific attributes to Talon.One's customer profile. This enables Talon.One's Rule Engine to apply dealer-specific and vendor-specific discount logic.

ℹ
Why profile data matters for AGCO promos
Promotions like Dealer Specific and Growth Commitment are tied to individual dealer accounts. The profile holds the dealer's tier, franchise type, previous year's sales volume, and qualifying vendor relationships — all referenced by Talon.One's rule engine during session evaluation.

Step 3 — Product Catalog

      
Ingesting AGCO Parts Attributes

      
Talon.One's Product Catalog stores part-level attributes that the Rule Engine uses to determine promotional eligibility. AGCO needs to sync the parts catalog — including vendor codes, DPM product types, MOQ values, and promo eligibility flags — so the engine can evaluate line-by-line discount conditions.

    


    

      
⚠

      

        
MOQ enforcement for Vendor Specific promos

        
Promos like "Minimum Volume" (e.g. 55 gallons from a single vendor) require MOQ values on the catalog item. If the dealer's quantity doesn't meet vendor MOQ, Talon.One returns a rejectCouponCode effect with a descriptive reason, and Hybris blocks order creation with the required error message.

Part attribute mapping to AGCO BRD

        

          

            
promoEligible

            
Determines if a line item qualifies for the promo discount. Non-eligible parts receive full Dealer Net pricing in the cart.

          

          

            
moqQty + moqUnit

            
Used by Talon.One rules to block order creation if vendor MOQ not met (e.g. 55 gallons). Returns blockEffect with error message.

          

          

            
dpmCategory

            
Maps to Growth Commitment promo categories. Rules evaluate DPM-specific parts toward growth target calculations.

          

          

            
isPrebook / isVendorSpecific

            
Routes items to OSP program logic or vendor-specific VRD tiers respectively. Controls allocation month via 4-digit promo code logic.

          

        

      

    

  


  


  
  

    

      
Step 4 — Collections

      
Campaign Targeting with Collections

      
Collections are reusable, dynamically-updated lists of SKUs or dealer IDs in Talon.One. They power AGCO's campaign targeting — defining which parts belong to a promotion and which dealers qualify — without hardcoding these in individual campaign rules.

Collection types for AGCO promos

        

          

            
📦

            

              
Part SKU collections

              
One collection per campaign (e.g. "harvest-2025-eligible-parts"). Rules check if cart item SKU is in collection. Supports mass upload from Hybris via Management API batch endpoint.

            

          

          

            
🏪

            

              
Dealer account collections

              
Controls which dealers see and can use a promo. Referenced in campaign conditions: "Customer profile ID is in collection [qualifying-dealers]".

            

          

          

            
🏭

            

              
Vendor SKU collections

              
For Vendor Specific promos, all SKUs from a given vendor are collected. Enables VRD tier calculation across any part from that vendor.

Step 5 — API Effects

      
Effects Engine & Response Handling

      
Talon.One's Rule Engine evaluates session data against campaign rules and returns an effects array. Each effect tells Hybris exactly what to do — apply a discount, block an order, award free freight, or accept/reject a coupon code. This single integration handles all promo logic without any custom discount code in Hybris.

    


    

      
✓

      

        
Key integration advantage

        
Once the effects response handler is built in Hybris, all future promo types (Annual, VRD, Growth Commitment, Clearance, etc.) are supported automatically — only the Talon.One campaign configuration changes, not the Hybris integration code.

      

    


    

      

        
✓

        

          
acceptCoupon

          
Promo code is valid and active. Hybris displays campaign name in cart and unlocks promo discount display.

        

      

      

        
✗

        

          
rejectCoupon

          
Promo inactive, dealer ineligible, or MOQ not met. Hybris displays error message. Order blocked for vendor-specific failures.

        

      

      

        
%

        

          
setDiscount

          
Core effect. Returns discount name and value in USD. Scope: session (order total) or lineItem (individual part). Applied directly in Hybris cart.

        

      

      

        
🚚

        

          
setDiscount (freight)

          
Free freight effect when minimum order value is exceeded. Hybris zeroes the shipping line and shows "Free Freight" label on cart and checkout.

        

      

      

        
⊗

        

          
addFreeItem

          
Used for bundle promotions. Hybris adds a zero-cost line item to the cart with the specified SKU and displays it as a promotional gift.

        

      

      

        
↯

        

          
setSessionAttribute

          
Used to stamp the campaign name, discount tier achieved, and promo reference onto the session — passed through to ERP with the order.

        

      

    


    

      
Hybris effects handler pseudocode

      

        

          

          hybris-promo-handler.js
        

        
// hybris-promo-handler.js — processes Talon.One effects array

function processEffects(effects, cart) {

  for (const effect of effects) {

    switch (effect.effectType) {

      case "acceptCoupon":
        cart.promoStatus      = "ACTIVE";
        cart.displayPromoName = effect.props.value;  // e.g. "HARVEST-2025"
        break;

      case "rejectCoupon":
        cart.promoStatus = "BLOCKED";
        showError(effect.props.rejectionReason);  // e.g. "MOQ not met for FENDT"
        break;

      case "setDiscount":
        if (effect.props.scope === "session") {
          cart.orderDiscount += effect.props.value;  // tiered % discount
        } else if (effect.props.scope === "additionalCost") {
          cart.shippingCost = 0;     // free freight threshold met
          cart.freeFreight  = true;
        }
        break;

      case "setSessionAttribute":
        // Stamps promo ref onto session → forwarded to S4 via middleware
        cart.erpAttributes[effect.props.key] = effect.props.value;
        break;

    }
  }

  return cart;
}

      

    

  


  


  
  

    

      
Step 6 — Multi-Market Rollout

      
One Integration, Built to Scale

      
The Talon.One integration is a one-time engineering effort. Once built, the same integration layer is reused as AGCO launches into new markets — each new country simply provisions its own Talon.One Application and API key, and the existing integration is ready to go.

    


    

      
🌍

      

        
One-time integration, reused across every market launch

        
The integration work — session handling, profile sync, effects processing, catalog ingestion — is done once. When AGCO goes live in Canada, the UK, or Australia, the same integration is reused: a new Talon.One Application is provisioned for that market, market-specific campaigns and collections are configured in Campaign Manager, and the existing Hybris integration points to the new api_key. No re-integration required.
